# Import loading and build.xsl ordering: probe evidence

Recorded on Windows PowerShell 5.1 (.NET Framework 4.8, CLR 4.0.30319.42000), NTFS, culture en-IN, on 2026-10-18. They back `spec/import-load.md` (`IMP-001` to `IMP-099`). Nothing here is Aras code or a credential.

| File | What |
|---|---|
| `load-package-dom.cases.json`, `load-package-dom.out.txt` | The real 14.0.7 `ImportExportManager.LoadPackageDom` (vendored `oracle/native/14.0.7/Libs.dll`, staged to `%LOCALAPPDATA%`) run on package folders built from the cases, then `GetItemsFromPackageDom` on its result. The output gives the result DOM's outer XML (CR and LF escaped as `\r` and `\n`), the item count, the log text, or the exception. The run folder is shown as `<ROOT>`. |
| `build-xsl.cases.json`, `build-xsl.out.txt` | The engine's own `build.xsl` (extracted from the DLL with ILSpy into the gitignored `.decomp/14.0.7/`) run through `XslCompiledTransform` with `ApplyXsl`'s settings. Each case lists the package files (`parts`, each a file's text). A part is stamped as `LoadPackageDom` stamps it (`k<n>` and `f<n>`). A line `type\|action\|id\|tempKeyName` is one output item; `RAW:` is the serialized output after the `xmlns:SOAP-ENV` replace. |
| `load-package-dom.out.14.35.txt`, `build-xsl.out.14.35.txt` | The two groups above run against 14.35 (vendored `oracle/native/14.35/Libs.dll`; `build.xsl` extracted into `.decomp/14.35/`), with the same case files. Both files are byte-for-byte equal to the 14.0.7 ones, apart from the machine's path and user name, which are scrubbed in both. They back the `[14.35]` lines of `IMP-001` to `IMP-015` and of `IMP-023` to `IMP-032`. (Run `lpd.ps1` with the two cases named `longpath` renamed apart, and `rd /s /q \\?\<run folder>` between engines: PowerShell 5.1 cannot delete the long-path folder.) |
| `build-xsl-cui.cases.json`, `build-xsl-cui.out.14.0.7.txt`, `build-xsl-cui.out.14.35.txt` | Seven cases for the two types 14.35's `build.xsl` adds, `cui_Control` and `cui_WindowSection`: their add and edit placement, their other actions, a substring run such as `Report\|Form`, and the copies after an `ItemType` add. Each case ran against both stylesheets, so the two outputs differ exactly where `IMP-021`, `IMP-022` and `IMP-029` say. |
| `load-package-dom.12.0.out.txt`, `build-xsl.12.0.out.txt` | The same two recordings through the 12.0 engine, for the `[12.0]` variants of `spec/import-load.md`. The first runs the vendored `oracle/native/12.0/Libs.dll` over `load-package-dom.cases.json` with the same `lpd.ps1`; the second runs the 12.0 `build.xsl` (extracted with ILSpy into the gitignored `.decomp/12.0/`) over `build-xsl.cases.json` with the same `probe.ps1`. They differ from the 14.0.7 files only where the 12.0 rules say: no `tempFullName`, the skip warning, the reader's decoding, UNC paths, and `mp_MacPolicy` `mp_PromoteItem` (case `drops`). |
| `load-package-dom.12.0-extra.cases.json`, `.out.txt` | Cases that only 12.0's reader tells apart (named `x-…`): encodings and byte-order marks, declared encodings that are right, wrong or unknown, invalid bytes, UTF-16 and UTF-32 without or with a mark, a file of only a mark, and file, folder and package names with `#`, `%`, `&` and other characters a URI would read differently. Recorded with `lpd.ps1` on the 12.0 engine. |
| `build-xsl.12.0-extra.cases.json`, `.out.txt` | Cases for the two `build.xsl` differences of 12.0: `ac_PolicyAccessItemAttribute` (unlisted, so every action lands in the last bucket) and `mp_MacPolicy` `mp_PromoteItem` (dropped). Recorded with `probe.ps1` and the 12.0 `build.xsl`. |
| `nls-word-sort.json` | Per-character NLS sort-key sections for the repertoire of IMP-030, and random type names with the order `xsl:sort select="@type"` gave them. |
| `invariant-upper.json`, `listing-order.json` | `ToUpperInvariant` differences for BMP code units, and `Directory.GetFiles` / `GetDirectories` results on NTFS for scrambled creation order. They back IMP-004. |
| `probe/` | The PowerShell that recorded the files above. `lpd.ps1 -Native <staged Import folder> -CasesFile load-package-dom.cases.json -Out <file>` runs the first group; `probe.ps1 -Xsl <build.xsl> -CasesFile build-xsl.cases.json -Out <file>` the second. Run them from a Windows folder (not `\\wsl.localhost`), staging the DLLs as `oracle/README.md` describes. `lpd.ps1` appends `2` to a case folder that already exists (two cases are both named `longpath`). |

`spec/import-load.test.ts` replays `nls-word-sort.json`, `invariant-upper.json` and `listing-order.json` against the reference algorithms written in the spec.

`src/import/ordering.test.ts` replays the same three files against the library's own NTFS order and NLS sort. `src/import/build-xsl.test.ts` replays `build-xsl.cases.json` and `build-xsl-cui.cases.json` (the 14.0.7 output) through the library's `build.xsl` ordering, and `src/import/load-package-dom.test.ts` replays `load-package-dom.cases.json` on package folders built in a temporary folder (not the three cases that need Windows: `hidden`, `locked`, `unc`).

# 14.0.7 import merge probe

What engine 14.0.7's own `CImportItems` and `CItemHelper` do on the merge and versionable paths, recorded once for ticket 21 (`spec/import-merge.md`).

- **Run:** `oracle/merge-probe/probe-14.0.7.ps1` loads the vendored 14.0.7 `IOM.dll` and `Libs.dll`. It drives the real `CImportItems` against `StubHelper.cs`, a scriptable `ICItemHelper` that records every call in order and answers from tables a scenario fills, and the real `CItemHelper` against the request probe's `StubConnection` (`oracle/request-probe/Stub.cs`). Nothing touches a network. There is no server, user or password, so nothing depends on dev and nothing needed scrubbing.
- **`results.json`:** `scenarios`, each a named group of cases (`V.validation`, `F.finalApply`, `M.merge`, `G.versionableMerge`, `C.ccrProperty`, `P.processVersionableItem`, `S.setItemIdToLastGeneration`, `E.doesItemAlreadyExist`, `X.lookups`). A `CImportItems` case holds the `input` item, `merge`, the `calls` the engine made to its helper in order (`applyAML <text>` is the exact string handed over), `thrown` and `documentAfter`, the item document's `OuterXml` when the call ended. A `CItemHelper` case holds the `requests` as IOM was handed them (wire text, double-quoted attributes), the `result`, `thrown` and `documentAfter`. `thrown` has the exception `type`, and for a `CItemException` the `faultcode`, `faultdetail`, `message`, and `faultstring` unless it is a stack trace (`faultstringIsStack`). Texts are clipped to 300 characters.
- **Not evidence of:** what the server answers. Answers are scripted, so which rows a `get` finds comes from the dev import fixtures of ticket 25. The stub helper's `applyAML` parses its argument first, as IOM does, so a malformed request fails with `XmlException` as it would for the engine; a stub's own wording of a fault (`fault 999`) is the stub's.

To re-record, run `oracle/merge-probe/run.sh` from WSL. It stages `oracle/native/14.0.7/IOM.dll` and `Libs.dll`, the request probe's `Stub.cs` and the probe files under `%LOCALAPPDATA%` (.NET refuses assemblies from `\\wsl.localhost`), runs the probe on Windows PowerShell 5.1, re-indents the JSON and deletes the staged copy.
